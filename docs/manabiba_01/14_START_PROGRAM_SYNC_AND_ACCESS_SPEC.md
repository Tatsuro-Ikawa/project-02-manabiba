# スタートプログラムの保存（端末間の共有）と利用条件（草案）

**位置づけ**: スタートプログラム（Step0〜7）の入力を、パソコンとスマホの両方で続けられるようにするための保存方式と、Step5 以降の利用条件（無料期間とスタンダード申込）を定める。
**関連**: [04_START_PROGRAM_SEVEN_STEPS_SPEC.md](./04_START_PROGRAM_SEVEN_STEPS_SPEC.md) §8（Firestore パス）、[12_STEP05_TIMELINE_SPEC.md](./12_STEP05_TIMELINE_SPEC.md) D17、[13_PLAN_JOURNAL_INTEGRATION_SPEC.md](./13_PLAN_JOURNAL_INTEGRATION_SPEC.md) D19・D25、[04_SUBSCRIPTION_PRODUCT_SCOPE.md](./04_SUBSCRIPTION_PRODUCT_SCOPE.md)、[04_STRIPE_BILLING_SPEC.md](./04_STRIPE_BILLING_SPEC.md)

---

## 1. 決定事項（2026-10-14）

| 項目 | 決定 |
|------|------|
| 保存先 | **Firestore を正本**にする。localStorage は端末ごと・ブラウザごとの保存で、パソコンとスマホの間で共有できないため、正本には使わない |
| 対象 | **Step0〜7 の全体**（Step5 は Step1〜4 を参照するため、一部だけサーバーに移すと別の端末で前提が欠ける） |
| 利用開始の条件 | **Google ログイン＋利用規約・プライバシー同意のみ**（カード登録なし） |
| 無料の範囲 | Step0〜4 は期限なしで無料。Step5 以降は **28 日間無料** |
| 28 日後 | Step5 以降を続けるには **スタンダード申込（カード決済）** が必要 |
| 決済の流れ | 開始時はカード登録なし。無料期間の終わりに申込画面でカードを登録し、決済する |
| 28 日お試し（気づきノート） | スタートプログラム経由の申込には **付与しない**（スタートプログラムの無料期間をお試しとみなす） |

## 2. 保存のしかた

### 2.1 基本の考え方

- **入力のたびに 1 文字ずつ保存はしない**。入力が止まったとき・区切りのときにまとめて保存する。
- 端末の中（localStorage）には **最新の状態と未送信の変更**を置き、表示の速さと通信が切れたときの備えにする。正本は常に Firestore。
- AI の結果も保存する。別の端末で開いたときに AI を作り直さないため（費用と待ち時間の節約）。

### 2.2 保存するタイミング

| タイミング | 保存のしかた | 例 |
|------------|--------------|-----|
| 文字の入力が止まって 2 秒 | まとめて保存（待ち時間の間の入力は 1 回にまとめる） | 目標の一文、現在の姿 |
| 入力欄から離れたとき | すぐ保存 | 次の欄へ移る |
| 選ぶ・押す操作 | すぐ保存 | 点数、◎○△、候補の採用、削除 |
| フェーズの移動・「次へ」 | すぐ保存（保存の完了を待ってから移る） | 「3方向で描く」→「自分らしさ」 |
| AI の結果が届いたとき | すぐ保存 | 候補、目標の一文、ひとこと |
| 画面を閉じる・別のアプリに切り替える | 未送信があれば送る | スマホでホームに戻る |
| 通信が戻ったとき | 未送信をまとめて送る | 電車の中で入力 → 駅で復帰 |

- 画面には保存の状態を小さく出す（「保存しました」「保存中…」「未送信（通信が戻ったら送ります）」）。
- 書き込み回数の目安は、1 時間しっかり入力して 100〜300 回程度。Firestore の費用としてはごく小さい。

### 2.3 読み込むタイミング

- 画面を開いたとき、アプリに戻ったとき（別のアプリ・タブから戻ったとき）に最新を取得する。
- 入力中に他の端末の内容で書き換わると混乱するため、常時のリアルタイム反映はしない。

### 2.4 ドキュメントの単位

既存の §8（[04_START_PROGRAM_SEVEN_STEPS_SPEC.md](./04_START_PROGRAM_SEVEN_STEPS_SPEC.md)）の考え方を引き継ぎ、Step ごとに 1 ドキュメントとする。

```
users/{uid}/start_program/{docId}
  docId = meta | step00 | step01 | step02 | step03 | step04 | step05 | step06 | step07
```

| フィールド | 内容 |
|------------|------|
| `payloadEncrypted` | Step の入力データ全体（JSON）を暗号化したもの。現在の localStorage の内容と同じ形 |
| `schemaVersion` | データの形の版（現在の `version` と同じ） |
| `rev` | 保存のたびに 1 増やす数値（端末間の食い違いの判定に使う） |
| `deviceId` | 最後に保存した端末の ID（端末ごとにランダムに作り、端末内に保持） |
| `updatedAt` | 最後に保存した日時 |
| `progress` | 進み具合（完了したフェーズなど・平文）。ホームの表示や利用条件の判定に使う |

- 暗号化は要件どおり行う（[04_TRIAL_28_IMPLEMENTATION_DECISIONS.md](./04_TRIAL_28_IMPLEMENTATION_DECISIONS.md) §10）。スタートプログラムの入力はサーバー側で検索しないため、項目ごとではなく **Step 単位でまとめて暗号化**する（項目の追加・変更に強い）。
- 計画（[13](./13_PLAN_JOURNAL_INTEGRATION_SPEC.md) §3 の `users/{uid}/plans`）は気づきノートから項目単位で参照するため、従来どおり項目ごとの `…TextEncrypted` とする。
- 1 ドキュメントの上限（1MB）に対して、Step5 の全領域分でも十分に小さい。

### 2.5 端末間の食い違い

同じ Step を 2 つの端末で同時に編集することはまれだが、次のルールで守る。

1. 保存時に、手元が知っている `rev` とサーバーの `rev` を比べる（トランザクション）。
2. 一致すれば保存し、`rev` を 1 増やす。
3. 一致しなければ（別の端末で先に保存されていれば）保存せず、「別の端末で更新されています。最新を読み込みますか？」と表示する。自動で混ぜ合わせはしない。
4. 最新を読み込まない場合は、手元の内容で上書きするかを確認する。

### 2.6 通信が切れたとき

- 入力は手元に保持し、「未送信」の印を付ける。
- 通信が戻ったら §2.5 のルールで送る。
- ログインしていない状態では使わない（Google ログインが前提のため）。

### 2.7 これまでの localStorage のデータ

- モック段階の localStorage のデータは、初回ログイン時に一度だけ Firestore へ移す（サーバー側にデータがない Step のみ）。
- 移したあとも localStorage は手元の控えとして使う（§2.1）。

## 3. 利用条件と申込

### 3.1 状態ごとの利用範囲

| 状態 | Step0〜4 | Step5〜7（AI を含む） | 気づきノート |
|------|----------|------------------------|--------------|
| フリー会員・無料期間中（開始から 28 日） | 利用可 | 利用可 | 利用不可 |
| フリー会員・無料期間後 | 利用可 | 見るだけ（入力・AI は不可）（D27） | 利用不可 |
| スタンダード／プレミアム | 利用可 | 利用可 | 利用可（28 日お試しなし・申込時から課金） |
| 解約後 | 利用可 | 見るだけ | 既存の失効後の扱いに従う |

- 無料期間の起点は **スタートプログラムを始めた日**（初回の同意日）とする（D26）。
- 無料期間の終わりは JST の日付で判定し、終了日の 23:59 まで使える。

### 3.2 案内の出し方

| 時期 | 案内 |
|------|------|
| Step5 に入ったとき | 「Step5 からは無料期間（残り ◯ 日）のあと、スタンダードコースでご利用いただけます」を一度だけ表示 |
| 残り 7 日〜 | Step5 以降の画面上部に残り日数を表示 |
| 期限後 | 入力欄を閉じ、「続けるにはスタンダードコースへ（入力した内容はそのまま引き継がれます）」と申込ボタンを表示 |

- 入力した内容は申込後もそのまま使えることを必ず伝える（申込への不安を減らす）。

### 3.3 利用者情報に持つ項目

`users/{uid}` に追加する（クライアントからは書き換えられないようにする）。

| フィールド | 内容 |
|------------|------|
| `startProgramStartedAt` | スタートプログラムを始めた日時 |
| `startProgramFreeEndsAt` | Step5 以降の無料期間の終わり（開始日を 1 日目として 28 日目の 23:59・JST） |

- 利用可否（entitlement）は「スタンダード／プレミアムが有効」または「現在が `startProgramFreeEndsAt` より前」で判定する。
- 判定は 3 か所で行う: 画面の表示、AI の API、Firestore のルール（Step5〜7 のドキュメントへの書き込み）。

### 3.4 申込（Stripe）

- 申込画面から既存のスタンダード Checkout を使う。ただし `startProgramStartedAt` がある利用者の初回申込は **`trial_period_days` を付けない**（決済は申込時から）。
- 初回クーポンの扱いは既存の Standard と同じにする。
- プレミアムを選んだ場合も 28 日お試しは付けない（D29）。
- Webhook で `plan` が有効になれば、Step5 以降の入力が再開できる（データは §2 で保存済みのため、そのまま続きから）。

### 6.1 データの保管（D28 の補足）

- 対象: 無料期間が終わり、申込をしていないフリー会員のスタートプログラムのデータ（Step0〜7）。
- 最終ログインから 90 日で削除する。削除の 14 日前と 3 日前にメールで知らせる。
- 期限後の Step5 以降の画面に「申込がない場合、最後のログインから 90 日で入力内容は削除されます」と表示する。
- ログインすれば起点が更新される（見るだけでも可）。

## 7. モックの範囲（2026-10-15）

Firestore・Stripe の組み込み前に、画面の動きを確かめるためのモック。

| 内容 | モックでの扱い |
|------|----------------|
| 利用状態 | localStorage `startProgram.access.mock` に開始日・コースを持つ。Step5 画面の切り替えボタンで「無料期間中（残り 20 日）／残り 3 日／期限後／スタンダード」を選べる |
| 案内 | Step5 に初めて入ったときの案内、残り 7 日からの残り日数、期限後の申込パネル（§3.2） |
| 見るだけ | 期限後はフェーズの中の入力・ボタンを無効にし、AI の自動実行も止める。フェーズの切り替えは可能 |
| 申込 | 申込内容の確認（28 日お試しなし・申込時から課金・入力は引き継ぎ）→「申し込む（モック）」でスタンダードに切り替え |
| 保存の状態 | 入力が止まって 2 秒で「保存しました」を表示。通信が切れているときは「未送信（通信が戻ったら送ります）」（実際の保存先は localStorage のまま） |

実装: `src/lib/startProgram/accessMock.ts`、`src/hooks/useStartProgramAccess.ts`、`src/hooks/useSaveStatusMock.ts`、`src/components/start-program/access/StartProgramAccessParts.tsx`、`Step05WorksheetPane.tsx`（期限後は `fieldset disabled` で見るだけ）。
