## 1. テストアカウントの初期化（再入会フローをやり直す）

### 結論（よくある誤解）

| 操作 | 再入会テストに足りるか |
|------|------------------------|
| **Firebase Authentication のユーザだけ削除** | △ 再ログインで `users/{uid}` が無ければ**新規プロファイル**が作られ、同意は未済みになる（**推奨の一手段**） |
| **Firestore `users/{uid}` ドキュメントだけ削除** | ◎ 同上（Auth は残す） |
| **同意フィールドだけ削除／未同意状態にする** | ◎ **同じ UID で何度でも**入会フローを再現できる（**いちばん手軽**） |
| **Auth も Firestore も削除** | ◎ 完全に新規ユーザー扱い |

**Auth の UID 以下を「全部削除」する必要はない。** 入会ゲートの正本は **Firestore の `users/{uid}`** である。

### 同意・入会で見ているフィールド（正本）

| フィールド | 用途 | 未設定時の挙動 |
|------------|------|----------------|
| `users/{uid}.consents` | **利用規約（章立て）＋プライバシー**の同意（1回のみ） | `/post-login` → `/consent?next=...` |

版の判定は `public/legal/terms.json` / `privacy.json` の `version`（現状 `2026-03-18`）と `users.consents` が一致している必要がある。

**7日間・気づきノートとも**、同意は `consents` のみ。利用規約内の該当章を読み分ける想定。

### パターン A：同意フローだけやり直す（推奨）

Firebase Console → Firestore → `users` → 対象 `{uid}` で **`consents` フィールドを削除**（または map ごと削除）  
→ 7日間・気づきノートいずれの導線でも `/consent` が再表示される。

（旧実装の `startProgram7dConsents` は **A案で廃止**。残っていてもアプリは参照しない。）

ブラウザでは **アプリからログアウト** → 再ログイン、またはシークレットウィンドウで確認。

### パターン B：プロファイルごとリセット

- **`users/{uid}` ドキュメントを削除**（サブコレクション `journal_*` 等も消えるので注意）。
- 次回ログインで `createDefaultUserProfile` が走り、`plan: free` 等の初期値で再作成される（`consents` は無い＝未同意）。

### パターン C：完全に別ユーザー

- 別 Google アカウントでログイン、または Auth のユーザを削除して同じメールで再登録。

### スタンダード／プレミアム試用時に触ることがあるフィールド（任意）

| フィールド | 用途 |
|------------|------|
| `subscription.plan` | `free` / `standard` / `premium` |
| `subscription.trialEndsAt` | 28日お試し終了（新規作成時は自動で+28日が入る場合あり） |
| `subscription.trialConsumedAt` | お試し再付与なし判定（仕様上） |

有料申込 UI（Stripe）は未実装のため、プレミアム挙動の確認は **Firestore で `plan` を手動変更**する前提でチェックリストに記載する。

### 注意

- **利用規約とプライバシーは別画面ではない。** いずれも **1画面**（`/consent`）でスクロール条文（規約は章立て＋プライバシー1本）＋**チェック2つ**（規約／プライバシー）＋「同意して続ける」。
- ランディング（`/trial_4w/landing`）はログイン済みでも「やってみる」から再入可能。ブロックされるのは **同意済みのあと、目的 URL へ直行してしまう**場合。同意を消せば再度 `/consent` が出る。
- `/start-program/consent` は **存在しない**（旧 URL は 404 相当。必要なら将来 `/consent` へリダイレクトを検討）。
